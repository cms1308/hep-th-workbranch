Read `harness/PAPER-REVIEW.md` for shared scope, authorization, validation and saving,
and `PAPER-STYLE.md` for prose. Use the requested passage or section; a whole-draft
request may be handled section by section without new approval at each boundary.

Read enough surrounding text to understand the argument. Check project-specific style
choices and any requested reference author. The optional Song analysis in
`harness/style/jaewon-song.md` offers examples; it is not a required vocabulary or
sentence pattern. An existing outline may help, but no paragraph map is needed.

## Edit for the reader

- Clarify overloaded sentences, ambiguous referents, unnecessary repetition and awkward
  connections. Keep definitions and explanations that the reader needs.
- Use concrete operations and a natural scientific register. First-person plural and
  direct declarative prose are both available; claim/evidence order follows the argument.
- Respect restrained punctuation and established terminology. Do not rewrite a sentence
  solely because it contains a semicolon, dash, colon or a term used only once.
- Preserve formulas, citations, qualifications, test ranges and scientific meaning.
  If a change needs a new physical claim, report the issue and consult its evidence;
  do not introduce it as a wording improvement.

If the user asks for suggestions or review only, return the affected text, the proposed
wording and a brief reason. Otherwise apply authorized edits. Honor explicit project
requirements for item-by-item approval, but do not impose them on every project.
No dated proposal ledger is needed unless requested or necessary for pending decisions.

After applied edits, reread the passage, compile if manuscript sources changed, and
follow the shared checkpoint procedure. Update an outline only if its content changed.
Report substantive wording changes and any unresolved claim issue, without listing
sentences that needed no change.
